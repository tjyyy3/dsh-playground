# 比赛材料权限

插件先确认当前对话已绑定赛题，并通过 DSH 工作区注册表确认任务目录。工作区内的普通文件可直接作为材料引用。无法确认工作区时，插件停止处理，不使用宿主进程目录作为默认范围。

材料在工作区外时，任务详情会显示“外部材料权限”。面板列出实际解析后的文件或目录，包含符号链接和 Windows junction 的目标。交接只解析路径和文件类型，授权前后都不读取材料全文、计算摘要或启动材料预检。

- **仅本次操作允许**是默认选项。授权覆盖本次材料引用操作或已明确请求的提交交接。Agent 只可在交接给出的文件或目录范围内读取。其他操作不能重复消费它。
- **本次任务内允许**可在同一任务中复用。面板提供撤销按钮。任务归档、会话释放、目录切换或宿主重启后失效。
- 文件授权只允许该文件。目录授权默认只包含目录本身及直接文件，用户可以主动勾选包含子目录。目录中的链接若指向授权范围之外，仍需另行授权。

材料权限绑定任务会话、工作区、比赛材料用途和上述路径范围。授权保存在宿主内存中，不会从历史对话恢复。材料权限和提交交接都可以通过宿主加载已有 Agent；若宿主更换了会话对象，旧授权会失效，必须重新请求，不能仅凭相同会话编号恢复授权。

材料引用授权不等于提交许可。记录引用不会创建或上传提交。提交仍需用户明确请求或点击提交按钮，并沿用次数和配额的额外确认规则。若提交时需要新的外部材料权限，面板会明确显示“允许引用并继续交接”。

登录时读取 CLI 凭据属于独立用途，不会生成材料权限。这里的规则只约束插件处理的材料，不替代 DSH 终端或其他 Agent 的文件沙箱。

## 用户操作来源

权限入口是工作台的 `playgroundQueries/materials` 调用。宿主检查 Gateway 注入的 `invocation.peer` 是否与 `connection.browserPeer` 为同一个对象。拥有 `owner` 标签的 API Peer、普通命令和 Agent 填写的确认参数都不能创建权限。没有可确认来源的宿主会拒绝授权。

这一判断核对了 DSH 安装包中的以下实现。

- `dsh-client-connection` 将通过浏览器认证的请求交给共享的 `browserPeer`，API 连接使用独立 Peer。
- `dsh-api-gateway` 将实际接纳的 Peer 放入调用上下文，不从请求参数读取它。
- `cordis` 的服务追踪将该上下文传给 `playgroundQueries`。
- `dsh-commands` 对命令统一记录 `source.kind = user`，因此这里不把命令日志当作用户授权证明。
- `dsh-storage-domain` 在工作区归档状态持久化后发出 `domain/changed`，用于立即撤销该任务的权限。

离线测试覆盖了工作区边界、单次消费、任务复用与撤销、目录范围、Windows junction、大小写路径、伪造来源和登录凭据的用途隔离。真实 DSH 工作台中的端到端交互仍需运行验证。Windows 文件符号链接测试在缺少系统权限时明确跳过，junction 测试仍执行。
